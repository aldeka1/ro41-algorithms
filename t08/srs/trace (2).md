# СРС 8. Трассировка методов string и StringBuilder

## 1. `s.Trim()` и `Split(';')`

Дано: `s = "  Ахметов Ерлан;85 "` (два пробела в начале, один в конце). Длина `s` = 19.

**Шаг 1. `s.Trim()`** убирает пробельные символы с начала и с конца строки и возвращает новую строку:

| Строка | Значение | Длина |
|--------|----------|-------|
| `s` до `Trim()` | `"  Ахметов Ерлан;85 "` | 19 |
| результат `Trim()` | `"Ахметов Ерлан;85"` | 16 |

**Шаг 2. `Split(';')`** для `"Ахметов Ерлан;85"` режет строку по символу `;` и возвращает массив из 2 элементов:

| Индекс | Содержимое | Длина | Пояснение |
|--------|------------|-------|-----------|
| 0 | `"Ахметов Ерлан"` | 13 | 7 букв + пробел + 5 букв |
| 1 | `"85"` | 2 | две цифры |

Длина массива = 2. Пробел внутри элемента 0 остаётся, потому что `Trim()` убирает пробелы только по краям.

## 2. `int.TryParse` для `line = "Иванов Пётр;70;85;x"`

`line.Split(';')` даёт массив из 4 частей. Для каждой выполняется `int.TryParse(часть, out int value)`:

| Индекс | Часть | Результат TryParse | Значение `out` | Почему |
|--------|-------|--------------------|----------------|--------|
| 0 | `"Иванов Пётр"` | `false` | 0 | в строке буквы и пробел, это не число |
| 1 | `"70"` | `true` | 70 | строка состоит из цифр |
| 2 | `"85"` | `true` | 85 | строка состоит из цифр |
| 3 | `"x"` | `false` | 0 | буква, не число |

При неудаче `TryParse` не бросает исключение, а возвращает `false` и записывает в `out` значение по умолчанию, то есть 0.

**Что вернёт `TryParseScores`.** Кода метода в задании нет, поэтому я исхожу из обычной логики такого метода: он разбирает оценки (части после имени) и возвращает `true`, только если разобрались все. Часть `"x"` не разбирается (`false`, `out = 0`), поэтому `TryParseScores` вернёт **`false`**: строка содержит некорректную оценку, и считать её целиком допустимой нельзя. Оценки 70 и 85 при этом разобрались успешно, но общий результат определяется «слабым звеном».

## 3. `s += i` и `StringBuilder.Append(i)`, цикл `for (i = 0; i < 4; i++)`

Строки в C# неизменяемы, поэтому `s += i` не дописывает символ в существующую строку, а создаёт новую (старая остаётся мусором для сборщика). `StringBuilder` хранит символы в своём внутреннем буфере (по умолчанию ёмкость 16) и дописывает в него без создания новых строк.

**Конкатенация `s += i`** (начальное `s = ""` — литерал, в подсчёт не входит):

| Шаг | i | `s` до | Операция | Новая строка | `s` после | Создано string всего |
|-----|---|--------|----------|--------------|-----------|----------------------|
| 1 | 0 | `""` | `"" + "0"` | `"0"` | `"0"` | 1 |
| 2 | 1 | `"0"` | `"0" + "1"` | `"01"` | `"01"` | 2 |
| 3 | 2 | `"01"` | `"01" + "2"` | `"012"` | `"012"` | 3 |
| 4 | 3 | `"012"` | `"012" + "3"` | `"0123"` | `"0123"` | 4 |

Итого: **4 новых объекта string** (по одному на итерацию), три из них (`"0"`, `"01"`, `"012"`) сразу становятся мусором.

**`StringBuilder sb = new StringBuilder(); sb.Append(i)`:**

| Шаг | i | Операция | Содержимое буфера | Новых string | Новых объектов StringBuilder |
|-----|---|----------|-------------------|--------------|------------------------------|
| 0 | | `new StringBuilder()` | пусто | 0 | 1 |
| 1 | 0 | `sb.Append(0)` | `0` | 0 | 0 |
| 2 | 1 | `sb.Append(1)` | `01` | 0 | 0 |
| 3 | 2 | `sb.Append(2)` | `012` | 0 | 0 |
| 4 | 3 | `sb.Append(3)` | `0123` | 0 | 0 |

Итого: в цикле **0 новых строк**, всего **один объект `StringBuilder`**; 4 символа помещаются в буфер ёмкостью 16, поэтому он даже не расширяется. Одна строка создаётся только в конце, если вызвать `sb.ToString()`.

**Вывод:** при многократной склейке в цикле `StringBuilder` выгоднее: `+=` создаёт новую строку на каждой итерации (с копированием всего накопленного текста), а `Append` меняет один буфер.

Примечание: в подсчёте не учтены временные строки, которые может создавать преобразование `i.ToString()`, а первая склейка с пустой строкой в реальной среде выполнения может вернуть уже готовую строку без копирования. Для учебной модели считаем одну новую строку на итерацию.

## 4. Почему `s.ToUpper()` без присваивания не меняет `s`

Строки в C# **неизменяемы (immutable)**: после создания объект string нельзя изменить. Метод `ToUpper()` не правит `s`, а создаёт и возвращает новую строку с символами в верхнем регистре. Переменная `s` продолжает ссылаться на прежний объект. Если результат вызова никуда не записан (нет присваивания), новая строка остаётся без ссылки и пропадает.

Пример для `s = "  Ахметов Ерлан;85 "`:

```csharp
s.ToUpper();      // создана "  АХМЕТОВ ЕРЛАН;85 ", но никуда не сохранена
// s по-прежнему "  Ахметов Ерлан;85 "

s = s.ToUpper();  // переменная s теперь ссылается на новую строку
// s == "  АХМЕТОВ ЕРЛАН;85 "
```

То же верно для `Trim()`, `Split()`, `Replace()` и других методов string: они возвращают новый результат, а исходная строка не меняется.
