# Трассировка: сортировка выбором, сортировка вставками, бинарный поиск

## 1. Сортировка выбором, a = {5, 2, 9, 1, 7}

На проходе i ищется индекс минимума среди элементов с индексами i..4, затем элемент с этим индексом меняется местами с a[i]. На проходе i выполняется n − 1 − i сравнений (n = 5).

| Проход i | Индекс минимума | Массив после обмена | Сравнений на проходе |
|----------|-----------------|---------------------|----------------------|
| 0 | 3 (значение 1) | {1, 2, 9, 5, 7} | 4 |
| 1 | 1 (значение 2, обмен с самим собой) | {1, 2, 9, 5, 7} | 3 |
| 2 | 3 (значение 5) | {1, 2, 5, 9, 7} | 2 |
| 3 | 4 (значение 7) | {1, 2, 5, 7, 9} | 1 |

Общее число сравнений: 4 + 3 + 2 + 1 = **10** (n(n − 1)/2 = 10, не зависит от исходного порядка).

## 2. Сортировка вставками, a = {4, 3, 2, 1}

На шаге i элемент key = a[i] сравнивается с элементами слева; пока левый элемент больше key, он сдвигается на одну позицию вправо, затем key вставляется на освободившееся место.

| i | key | Число сдвигов | Сравнений | Массив после вставки |
|---|-----|---------------|-----------|----------------------|
| 1 | 3 | 1 (сдвинут 4) | 1 | {3, 4, 2, 1} |
| 2 | 2 | 2 (сдвинуты 4, 3) | 2 | {2, 3, 4, 1} |
| 3 | 1 | 3 (сдвинуты 4, 3, 2) | 3 | {1, 2, 3, 4} |

Всего сдвигов: 1 + 2 + 3 = **6**.

На уже отсортированном массиве из 4 элементов на каждом шаге i = 1, 2, 3 выполняется ровно одно сравнение (a[i − 1] > key ложно, сдвигов нет), то есть всего **3 сравнения** и 0 сдвигов.

## 3. Бинарный поиск в a = {1, 3, 5, 7, 9, 11, 13}

Индексы 0..6. Границы lo и hi включительно, mid = (lo + hi) / 2 (целочисленное деление), цикл идёт пока lo ≤ hi. Если a[mid] = x, элемент найден; если a[mid] < x, то lo = mid + 1; иначе hi = mid − 1.

### x = 7

| Шаг | lo | hi | mid | a[mid] | Решение |
|-----|----|----|-----|--------|---------|
| 1 | 0 | 6 | 3 | 7 | 7 = x, найден, индекс 3 |

Поиск заканчивается за один шаг, результат: индекс **3**.

### x = 6

| Шаг | lo | hi | mid | a[mid] | Решение |
|-----|----|----|-----|--------|---------|
| 1 | 0 | 6 | 3 | 7 | 7 > 6, hi = mid − 1 = 2 |
| 2 | 0 | 2 | 1 | 3 | 3 < 6, lo = mid + 1 = 2 |
| 3 | 2 | 2 | 2 | 5 | 5 < 6, lo = mid + 1 = 3 |
| 4 | 3 | 2 | | | lo > hi, цикл закончен |

Поиск заканчивается без нахождения: элемента 6 в массиве нет (обычный бинарный поиск вернёт «не найден», например −1). При этом на выходе lo = 3 — позиция, куда 6 нужно вставить, чтобы массив остался отсортированным.

**LowerBound(6) = 3**: это первый индекс, для которого a[i] ≥ 6 (a[3] = 7). Тот же результат даёт трассировка LowerBound с полуоткрытым интервалом [lo, hi):

| Шаг | lo | hi | mid | a[mid] | Решение |
|-----|----|----|-----|--------|---------|
| 1 | 0 | 7 | 3 | 7 | a[mid] ≥ 6, hi = 3 |
| 2 | 0 | 3 | 1 | 3 | a[mid] < 6, lo = 2 |
| 3 | 2 | 3 | 2 | 5 | a[mid] < 6, lo = 3 |
| 4 | 3 | 3 | | | lo = hi, возвращается 3 |
